# ByteArena

Веб-платформа для проведения любительских киберспортивных турниров. Запустить турнир можно за несколько минут, без таблиц и без ручной работы с результатами.

> 🚧 Проект в разработке. Сейчас мы делаем нулевую версию (MVP), подробнее в разделе [Дорожная карта](#дорожная-карта).

## Зачем это нужно

Организаторы любительских турниров собирают сетки в таблицах, договариваются о матчах в чатах и сами считают результаты. На это уходят часы, и многие из-за этого вообще не берутся за турниры.

ByteArena сокращает путь от идеи до работающего турнира до нескольких минут и по возможности убирает ручную работу с результатами.

## Для кого

- **Компьютерные клубы**: локальные турниры, которые привлекают посетителей.
- **Студенческие и школьные киберспортивные клубы.**
- **Discord-сообщества и компании друзей**, которые хотят сыграть свой турнир.

## Возможности

- **Турнир за пару минут.** Организатор вводит название, дату и число команд, а платформа создаёт страницу турнира со ссылкой для участников.
- **Автоматическая сетка.** Сетка строится сама, и победитель матча переходит в следующий раунд без ручных подсчётов.
- **Вход в один клик.** Игроки заходят через Discord, регистрируют команду и сразу видят свои матчи.
- **Всё в одном месте.** Регистрация, расписание, результаты и сетка находятся на одной странице.
- **ИИ-помощник организатора** *(в планах)*. Генерирует описание турнира и короткие новости после матчей.

Стартуем с **CS2**, затем добавим другие игры.

## Основные экраны

| Экран | Что на нём |
|---|---|
| Главная | Ближайшие и идущие турниры, кнопки «Создать турнир» и «Войти через Discord» |
| Создание турнира | Форма: название, дата и время, число команд, правила |
| Страница турнира | Описание, правила, список команд, регистрация, а после старта ещё и сетка с результатами |
| Регистрация команды | Название, состав (капитан, основные игроки, запасные), подтверждение участия |
| Страница матча | Команды, время, статус, итоговый счёт |
| Профиль игрока и команды | Ник, аватар, команда, сыгранные турниры |
| Панель организатора | Подтверждение команд, запуск турнира, внесение и правка результатов |

Основной сценарий: **создал турнир → зарегистрировал команду → увидел сетку → открыл матч**.

## Запуск проекта

Нужны Git и Docker Desktop.

```bash
git clone https://github.com/fendercm/ByteArena.git
cd ByteArena
cp .env.example .env          # один раз, потом заполнить свои значения
docker compose up --build
```

| Адрес | Что там |
|---|---|
| http://localhost:8080 | сайт (Next.js) |
| http://localhost/api/health | проверка бэкенда, ответ `{"status":"ok"}` |
| http://localhost/api/docs | документация API |
| localhost:5432 | PostgreSQL (логин и пароль из `.env`) |

Полезные команды:

```bash
docker compose logs -f backend   # логи бэкенда
docker compose down              # остановить
docker compose down -v           # остановить и стереть базу
```


## Возможные проблемы и решения (Troubleshooting)

### 1. Занят порт 8080 (`bind: address already in use` / `socket access permissions`)
Порт `8080` на хост-машине уже занят другим приложением (другой веб-сервер, проект на Node.js/Java или локальный прокси).

- **Windows:**
  Найдите PID процесса, занявшего порт, и остановите его:
  ```powershell
  # 1. Поиск PID процесса, слушающего порт 8080:
  netstat -ano | findstr :8080
  # 2. Завершение процесса по найденному PID (например, 12345):
  taskkill /PID 12345 /F
  ```

- **macOS / Linux:**
  Определите и завершите процесс командой:
  ```bash
  # Найти PID и принудительно остановить процесс на порту 8080:
  lsof -ti :8080 | xargs kill -9
  ```

> **Важно по Discord OAuth:** Так как платформа работает на порту `8080`, обратный адрес (Redirect URI) в Discord Developer Portal должен быть зарегистрирован с портом `8080`

---

### 2. Конфликт порта базы данных 5432 (`address already in use`)
Порт `5432` занят локально запущенным экземпляром PostgreSQL вне Docker.

- **Windows:** откройте диспетчер служб (`Win + R` → `services.msc`), найдите службу `postgresql-x64-<версия>` и остановите её (либо через консоль Администратора: `net stop postgresql-x64-16`).
- **macOS:** остановите службу Homebrew:
  ```bash
  brew services stop postgresql
  ```
- **Linux:** остановите системный демон:
  ```bash
  sudo systemctl stop postgresql
  ```

---

### 3. Не открывается `localhost` при включенном VPN
Корпоративные или публичные VPN-клиенты могут перехватывать системный DNS-резолвинг или некорректно маршрутизировать loopback-подсеть (`127.0.0.0/8`).

- Открывайте проект по прямому IPv4-адресу с указанием порта:
  `http://127.0.0.1:8080`
- Добавьте адреса `localhost` и `127.0.0.1` в список исключений (Bypass / Split Tunneling) в настройках вашего VPN-клиента.

---

### 4. Ошибка подключения к Docker Daemon (`Cannot connect to the Docker daemon...`)
Docker Engine не запущен, либо зависла виртуальная машина подсистемы WSL2 на Windows.

1. Убедитесь, что приложение **Docker Desktop** запущено и статус в левом нижнем углу окна зелёный.
2. Если Docker Desktop на Windows зависает на этапе «Starting Docker Engine»:
   - Полностью закройте Docker Desktop.
   - В PowerShell от Администратора выполните принудительный сброс подсистемы:
     ```powershell
     wsl --shutdown
     ```
   - Запустите Docker Desktop заново.
